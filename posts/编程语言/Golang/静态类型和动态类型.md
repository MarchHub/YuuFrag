# 静态类型和动态类型

应该算是 `interface` 的 dlc 吧

静态类型决定了在编译时候允许的行为，但是 `interface` 可以携带运行时动态类型，这样在运行时根据当前接口存储的动态值决定其行为（调用哪一个具体实现）—— 说简单些，即 “运行时多态”

比如在 `C++` 中，我们通过 `virtual function`，利用继承的关系然后 `override` 实现；

在 `golang` 中也是类似的道理，不过之前说过，我们不再是显式地写出继承关系，比如 `xxx impls some interface` 之类的，而是隐式的只要实现即可。所以一个 `interface` 类型在 runtime 会根据其存储的不同动态值，有不同的表现

## 静态类型

常见的 ——

```go
var x int = 114
b := 514
```

类似于 `x`，已经指定了为 `int`，所以其静态类型即为 `int`，那么编译期间也要求 `x` 所有行为都需要符合在 `int` 所实现的行为集合中

`b` 经过类型推断也会成为 `int`，所以依旧是静态类型，且为 `int`

综上，对于一个变量来说，其静态类型是在编译期就确定的，原则上不会改变

## 动态类型

基本上是对于接口而言，不过实际上所有类型都默认 impl 了 `interface{}`，所以其实这种理解应当推广到 golang 中的所有变量上

比如 ——

```go
var p any = Player {HP:114}
```

那么 `p` 的静态类型为 `any`，但是其动态值存储的是 `Player`；不过由于其依旧是空接口类类型，所以实际上 `Player` 类型中的各种方法等，依旧无法调用

或许此处借一下 C# 的思想 —— 万物皆 `Object` 可以比较好解释；也就是相当于 `Player` 类型其实隐式的继承了 `Object` 类型，然后 `p` 作为夫类的一个实例（其静态类型为 `any`），所以也只能调用父类中有的方法（此处恰好是空）

那么就非常容易看出

```go
var x any = Player{HP: 100}

fmt.Println(x.HP) // 编译错误
```

此处会触发编译错误

这也就非常好解释下面的代码可以顺利运行 ——

```go
var x any
x = 114
x = "514"
x = Player{ HP:114 }
```

说的文邹邹一些，即 `x` 的动态值一直在变化。不过实际上就是父类不断的被赋值成为其子类实现，十分甚至九分的简单

## 综上所述

那么实际上可以这么理解 —— 静态类型说明了该类型的 “能力”，而动态类型则为其在 Runtime 的具体实现行为 —— 运行时多态！！
