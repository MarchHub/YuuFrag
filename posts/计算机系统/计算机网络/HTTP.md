# HTTP

一个应用层协议，定义了客户端和服务端之间如何表达请求、传递资源以及描述处理结果

“无状态” —— 每一次的请求原则上独立，这样设计简单，在实践中可以利用 Cookie，Session 等进行身份识别

在 `HTTP/1.1` 中，默认支持持久连接（建立 TCP 握手之后，在一次请求完成之后不是立即断开链接，而是持续保持 TCP 连接状态），这样多个请求可以复用 TCP 连接，不过缺乏帧级别的多路复用 —— 比如通过 `HTTP/1.1` 顺序请求了 `temp.mp4`, `index.html`, `index.css`，那么它会阻塞在 `temp.mp4` 传输完毕之后再进行之后资源的传输，也就是常说的HTTP层队头阻塞问题 —— 一个请求响应慢的时候，阻塞之后的所有请求

那么在 `HTTP/2` 中，通过多路复用的方式解决了HTTP层的队头阻塞问题 —— 即通过切帧，多个请求的帧之间允许交错传输，这样就不会阻塞请求，不过由于依旧采用一条 TCP 连接，而其本身要求按顺序交付字节，所以实际上依旧存在传输层的队头阻塞问题

最后在 `HTTP/3` 中，利用 QUIC 作为传输层协议，实现可靠传输、多 Stream、拥塞控制，并集成 TLS 1.3，避免了单个 Stream 丢包直接阻塞其他 Stream 的交付

但是 HTTP 本身不提供加密 / 身份认证等，所以提出 HTTPS 来建立安全通信环境 —— 引入 TLS 层来实现服务端和客户端的身份认证 / 数据加密 / 验证数据完整性，那么这个蹲一篇 HTTPS / TLS 的笔记进行说明罢
